## D-01：陽奈戀愛線的時間與關係設定

- **狀態：** 以推薦方案作為章節規劃工作設定；成年篇年限、身分與具體呈現仍待章綱確認。
- **背景：** 參考開場由老師視角與陽奈互動；企劃目標為戀愛 Galgame，而陽奈的原作學生身分使戀愛關係的時間設定很重要。
- **選項：**
  1. 原作校園時期維持師生信任與照顧，不將其標為戀愛。
  2. 明確戀愛線發生於陽奈成年、畢業後，且師生指導／權責關係已結束的未來篇章。
  3. 改成同齡原創玩家角色或平行世界設定，保留校園戀愛。
- **推薦：** 以 1 作為校園篇基調，並以 2 作為目前正式戀愛線的暫定設計；保留原開場的老師視角，情感進程分成校園期的信任累積與成年後的戀愛發展。若故事聖經章綱無法自然交代時間跳躍與身分轉變，再評估選項 3。
- **理由：** 盡可能保留使用者提供的開場與老師視角，同時讓戀愛主題有清楚、負責任的時間定位。
- **影響：** 後續全篇章節須區分校園篇與成年後篇；校園篇只呈現信任、依賴與關心，不先宣告互相戀愛。此推薦仍可由使用者修正。

## D-02：篇幅統計的「字」如何計算

- **狀態：** 暫定採用推薦方案。
- **推薦：** 單節字數以正文可見中文字元與標點估算；Galgame 標記、選項字母、空行不納入。旁白／對話句數另記，不以 token 換算。
- **理由：** 使用者以中文「字」描述篇幅，按文字稿可直接檢查且容易跨節比較。
- **影響：** 逐節創作時附簡短統計；總篇幅以各節正文累計。

## D-05：離線時讓 GitHub Pages 續作的雲端工作方式

- **狀態：** 已放棄，專案不因此項阻塞後續迭代。
- **決定：** 使用者決定先不私有化 repo、不啟用 Copilot Automations。
- **使用者選擇：** 採用「將 repo 設為私有並建立 Copilot Automation」。
- **現況：** GitHub API 回覆私有化操作 403，瀏覽器環境也被網路策略阻擋，因此目前無法由主機代為變更 repo 可見性或建立 Automation。
- **實際啟用步驟：**
  1. 在 https://github.com/310111-design/hina-galgame/settings 開啟 Danger Zone → Change repository visibility，確認變更為 Private。
  2. 在 repo 設定確認 Copilot／Automations 可用；目前 live 設定回報 `automations_enabled=false`、`can_manage_automations=false`。
  3. 私有化並取得管理權後，建立一個 personal Automation；不需建立 automation group。
  4. 先建立為 `disabled: true`，只授予 repos、issues 與 actions 的必要讀寫工具；依實際設定選擇每日排程、手動 Run now 或 issue/PR 事件。
- **推薦 Automation 職責：**
  - 優先讀取 `knowledge/plan.md` 與 `knowledge/experience.md`。
  - 選擇路線圖中最靠前且無需人工偏好的可完成階段。
  - 需要玩家偏好、版權或重要世界觀決策時，寫入 `knowledge/decision.md`，並繼續不受阻塞的工作。
  - 完成段落後更新 `knowledge/experience.md`、勾選 `knowledge/plan.md`、提交分支並 push 到 `main`。
  - Pages 內容由 `.github/workflows/pages.yml` 自動部署；不要把企劃展示頁描述成已完成遊戲。
- **理由：** Copilot Automation 可在離線主機及瀏覽器關閉後由 GitHub 雲端執行；私有化是目前這個公開 repo 啟用該功能的必要前置條件。

## D-11：全螢幕呈現與瀏覽器相容策略

- **狀態：** 已採用推薦方案並完成第一版實作。
- **背景：** 使用者確認遊戲畫面比例為 fullscreen，但不同瀏覽器對 Fullscreen API 的支援不一致，尤其行動瀏覽器不應假設可由網頁強制進入原生全螢幕。
- **推薦／決定：** 以 CSS 全視窗版面作為預設；另提供使用者主動點擊的 Fullscreen API 切換按鈕。若瀏覽器不支援，遊戲仍以完整視窗版面運作，不阻斷遊玩。
- **理由：** 同時滿足沉浸式畫面目標與手機瀏覽器相容性，避免把遊戲是否可玩依賴於全螢幕 API。
- **影響：** 後續驗收需分別測試一般全視窗版面與瀏覽器支援時的原生全螢幕切換；不可把按鈕可見等同於所有裝置皆支援 Fullscreen API。
