## 可重用方法與未來適用範圍

1. **先同步，後宣稱盤點涵蓋稿件。** runtime 數字只有在 Markdown 逐句與分段一致時，才能同時代表稿件；選項文字另驗，不混入正文。適用於資料驅動小說、字幕與多來源內容發布。
2. **總稿量、去重稿量、單次閱讀量分開。** 共通只計一次的全分支總量不是玩家單次讀到的長度；單一路徑保留实际出現的重複台詞，去重只用於全篇唯一文字盤點。適用於多分支小說、路線估時與編輯工作量統計。
3. **明示 Unicode 單位。** String.length 是 UTF-16 code units，Array.from 是 code points，兩者都不是 grapheme；同時輸出非空白計數可避免空白造成假增長。用含 emoji／空白的 fixtures 證明差異，不因目前中文稿三者相同就混稱。適用於多語言遊戲、emoji 字幕及跨工具篇幅對照。
4. **有意義的合成反例比只驗目前數字可靠。** 使用不同說話者的相同文字驗精確去重；加入很長的選項與條件台詞，確認不污染基準路徑；非法 tuple 明確拋錯，不默認成空字串。適用於統計器與內容資料 schema 漸進驗證。
5. **盤點不應偷偷改發布門檻。** 早期章節不達參考值可輸出 advisory，保留後續品質工作，不擅自關閉既有成年篇門檻或為了 CI 灌水。適用於分階段品質提升、歷史資料稽核與技術債治理。
6. **指紋鎖定數值的來源版本。** 記錄 JSON 節點 SHA-256 及計數定義，資料變更即要求重算；節點 hash 不是整檔 hash，也不能代替 Git／部署證據。適用於可重現的章節審核、素材清冊與統計報告。
7. **編號相同不代表問題相同。** 本輪發現 plan 和 BMT review 的 BMT-07 指涉不同問題，後續用文件路徑＋標題追蹤；同步通過只證明兩份內容相同，不證明時間線缺口已修。適用於多輪審校、工單遷移與合併衝突後的知識維護。
8. **截斷文件不可整檔覆寫。** 即使能看到待勾項目，未讀尾段仍可能含重要歷史；將完成證據與待合併勾選存短補記，明說主檔尚未更新，不用驗證器執行文件改寫來繞過工具限制。適用於受限 API 代理及大型文檔維護。
