## 可複用方法及未來適用範圍

1. **把計數事件拆開。** 展開文件、編修版本、退件、送出、核准是不同狀態；三次重做不等於三次提交。第二次提交可等於第一次重新提交，未見核准時不替角色補成通過。適用於流程型劇情、調查進度、交接與任務狀態審校。
2. **條件命中不是回憶成立。** A02 ordinary_day 可以只由 P03 A「提出下次願望」取得，不能推定共同離室散步。先找最少事件即可命中的反例；通用旗標對應概括回憶，精確事件才用專用旗標。適用於所有累積旗標、成就和跨章回憶。
3. **條件的時間也要查。** flaggedIntro 在下章 choices 前，不能拿下章選擇替已顯示台詞補前提；「上次」又可能被理解成緊接前章，泛指歷史時改用「之前」。適用於章節自由重玩與多節共通事件。
4. **選項是玩家收到的承諾。** 「明天再做」和「今天只作暫時工具」雖有同樣的日常旗標，仍是不同後果；共通段今天完成會否定前者。修 label 可比重寫所有分支更小且準確，但須同步 runtime choices。適用於選項影響、分支 UI 文案和假選擇檢查。
5. **欄位同樣是道具狀態。** 資訊／判斷／確認不會自動變成本人決定／交付／等待；明寫重排動作，比持續新增抽象感想更能保持清楚。適用於包含表格、清單、地圖與線索板的故事。
6. **逐步擴充固定驗證，不先改大檔。** 完整可讀的小型 validator 可安全新增只讀檢查，即使 runtime 超出工具回傳長度，validator 仍可讀全檔比對。不得借 validator 寫檔或執行命令繞過工具限制。適用於受限工具下的可靠增量工作。
7. **解析規則按章稿格式限定。** A01/A02 的裸情緒標記是演出提示，不等於 runtime 空台詞；只對新加入的早期 dialogue-only 目標略過，成年篇解析與篇幅門檻保持不變。不要將『可見字數目標』當『正文統計』。適用於新舊稿件混用格式的同步遷移。
8. **展平逐句同步不等於語義通過。** 本批 330 條正文完全一致仍有 AAT 問題；展平比較還不能發現分段邊界漂移或 choices label 錯誤。適用於制定分層驗收：資料 schema→內容同步→分支狀態→人工／實機 QA。
