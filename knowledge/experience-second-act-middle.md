## 可重用方法與未來適用範圍

1. **一致不等於正確，不一致也不一定要改 runtime。** 新增章稿比較時先保留失敗證據，再區分稿件漂移與真正遊戲缺陷。本輪 runtime 已有正確單層引號，只修小型稿件即可恢復同步，不必等待大型 runtime 編輯工具。適用於逐批接入同步 CI、舊稿回填、資料生成後的人工排版錯誤。
2. **診斷列出兩側 tuple，不靠猜行號。** 驗證器列出每個差異的稿件與 runtime 值，能核對文字、說話者和情緒；這是唯讀診斷，不藉 validator 執行編輯或任意命令。適用於大型 runtime 難以完整預覽的資料校對；更大規模時可限制診斷數並保留總差異數，以免輸出過量。
3. **測試情節也有分支前提。** 共通試走如果驗收 B 分支才定義的欄位，仍然會抹平 A/C，不能只檢查共通首句的成果列舉。適用於教學、任務驗收、推理揭露及所有具有共通示範的互動小說。
4. **期限追蹤應包含執行者和狀態。** 用「任務／今晚必做步驟／負責人／完成或待回查／下一期限」檢查出口；已排順序、已交付、已核對是三種不同狀態。適用於期限衝突、分工交接、隔日任務及存檔摘要的語義設計。
5. **估時下限與完整工時分開。** 二十分鐘加十分鐘可等於兩項十五分鐘第一輪，不代表已含例外、排版與最後判斷。先確認被估算的工作範圍，再判算術矛盾，避免假陽性。適用於倒數、日程、戰術準備與有精確時間的敘事。
6. **章節目標也需隨修訂回查。** 移除共通的分支限定事件後，舊 metadata 的「首次主動求助」可能已無台詞支撐；應重新校準目標或補不同的分支行為，不能為滿足舊目標恢復已刪除的錯誤。適用於去重、縮寫、共通回收改稿與角色成長線。
7. **不把歷史規模當現況。** B05 現為 57 條 tuple，與早期擴寫紀錄不能直接互換；此輪不從 tuple 推算字元，將最新篇幅重算列後續。適用於反覆縮寫與長篇容量管理。
