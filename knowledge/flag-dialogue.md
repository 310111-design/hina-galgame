# 跨章節旗標對話表

本檔是遊戲條件對話的文字來源。對話在指定章節的 intro 結尾、選項出現前追加；未達門檻時不顯示。實際遊戲資料同步在 `site/game-data.js` 的 `flaggedIntro` 欄位，判斷由 `site/game.js` 的 `getSequence()` 負責。

## A02：退回的公務

- **條件：** `rest >= 1`
  - 【旁白】你記得之前她願意先停下來十分鐘。今天桌角仍留著那張便條。
- **條件：** `teamwork >= 1`
  - 【陽奈｜安心】「上次一起確認的分工方式，我還留著。今天也先分清楚判斷和整理。」
- **條件：** `ordinary_day >= 1`
  - 【旁白】你記得她曾想把一段時間留給公務以外的事。今天，你也沒有急著把話題限定在退件上。

## B01：工作量增加的一天

- **條件：** `daily_checkin >= 1`
  - 【陽奈｜微笑】「上次說好要留下的時間，我今天也先寫進安排裡了。」
- **條件：** `teamwork >= 2`
  - 【旁白】你注意到陽奈已經把可以交付的第一輪確認列在清單上，這次沒有等到工作堆滿才開始分工。

## C01：交接之後

- **條件：** `teamwork >= 2`
  - 【陽奈｜安心】「之前一起整理的交付規則，現在其他人也能獨立使用了。」
- **條件：** `self_rest >= 1`
  - 【旁白】陽奈在行程旁留了一段沒有公務名稱的空白，並沒有急著用新的任務填滿。

## D01：再次見面

- **條件：** `self_rest >= 1`
  - 【旁白】多年後再次見面時，你仍記得她曾練習替自己留白；現在她也能自然地安排自己的時間。
- **條件：** `ordinary_day >= 2`
  - 【陽奈｜微笑】「以前那些沒有特別目的的日子，我也一直記得。」

## 維護規則

1. 新增條件對話時，先更新本檔，再同步 `site/game-data.js`。
2. 旗標名稱必須存在於 `defaultState().flags`；門檻使用正整數。
3. 條件台詞只補充互動記憶，不得藏入必要主線資訊；未達條件時主線仍須完整。
4. 更新後檢查章節 ID、條件旗標、門檻和台詞陣列，並在 `knowledge/experience.md` 記錄可複用做法。

  - 【旁白】她提起那些普通日子，說自己想讓彼此的相處落在真實生活裡，而不是只留在重要時刻。
