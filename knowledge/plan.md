## 1. 最終願景

把目前可玩的文字劇情網頁，逐步完成為一部以空崎陽奈為核心、具有完整場景美術、角色表演、分支敘事與閱讀管理功能的沉浸式視覺小說（Visual Novel / Galgame）。

### 1.1 玩家體驗

1. 開啟即進入作品，不像一般企劃網站；主要畫面以背景、陽奈立繪及底部對話框構成。
2. 背景隨章節／劇情地點變化，並以光線、時間及氣氛拉開場景差異。
3. 陽奈以一致的正式立繪和表情差分演出，重要情節可使用事件 CG。
4. 對話逐字顯示；點擊時若句子尚未顯示完，先顯示完整句，再次點擊才推進。
5. 玩家可在遊戲主要空白區點擊推進；按鈕、選項與選單不會誤觸推進。
6. 重要選擇會影響後續對話、事件及成年篇關係路線，而不是只有當下短分支。
7. 可隨時查看對話紀錄、選擇章節、存檔／讀檔及調整音量。
8. 手機直向、平板、桌面與橫向手機皆可清楚閱讀及操作。

### 1.2 故事願景

- 基調：甜甜日常 × 酸甜青春；以細膩環境、自然對話、角色神情及生活互動建立情感。
- 校園篇：以信任、照顧、合作與逐漸理解為主，不將校園時期的師生互動直接寫成戀愛關係。
- 成年篇：學生時代結束五年後，於車站附近的獨立咖啡店重逢；雙方已無師生／指導權責，以平等且自主的成年人身分重新認識彼此。此為同人創作設定，不代表官方正史。
- 成年篇正式關係方向由玩家明確選擇，分為三條路線：
  - **朋友線：** 保留深厚信任，成為能自在分享生活的朋友。
  - **搭檔線：** 以互相支持、共同完成目標及尊重彼此專長為核心。
  - **戀愛線：** 在成年後的相處中逐步確認感情，建立雙向且自主的關係。
- 校園篇早期選擇可影響三條路線中的共同回憶、熟悉程度與對話細節，但不應單靠隱藏分數替玩家決定關係。
- 三條路線應有專屬事件、關鍵對話及各自結局；共通章節仍保留，避免三條路線只是更換結尾文字。

### 1.3 篇幅與節奏目標

- 全篇唯一正文目標：約 80,000～150,000 字。
- 全篇旁白／對話句數：約 3,000～5,000 句。
- 單節目標：約 2,500～4,000 字、約 80～130 句，閱讀約 8～12 分鐘。
- 分支統計以所有唯一正文累計，共通段落只計一次，互斥分支分別計入；另可估算單一路線的實際閱讀量。
- 以上為長期目標，實際以劇情節奏和分支品質優先，不為湊數灌水。

## 2. 已定案的設計決策

以下決策直接作為後續實作規格，不再視為待確認事項。

| 項目 | 定案 | 實作準則 |
|---|---|---|
| 畫面比例 | **fullscreen** | 預設使用 CSS 全視窗沉浸式版面；支援時另提供使用者主動開啟原生全螢幕。 |
| 背景更換 | **chapter** | 以章節作為主要背景配置單位；同章有明確地點轉換時可切換場景。 |
| 章節解鎖 | **all** | 所有章節皆可自由選擇，不要求依序解鎖。 |
| 存檔方式 | **both** | 自動存檔＋多個手動存檔欄位；顯示章節、時間及進度。 |
| 裝置介面 | **adaptive** | 手機、平板、桌面自適應；優先照顧手機觸控與安全區。 |
| 成年篇關係 | **朋友／搭檔／戀愛三線** | 成年篇由玩家明確選擇；早期旗標只調整回憶與互動細節。 |
| 文字呈現 | **逐字顯示** | 點擊先完成當句，再次點擊推進；提供自動播放與速度設定。 |
| 選項位置 | **底部對話框內** | 選項在對話框中呈現，手機直向改為易點擊的直列。 |
| 對話紀錄 | **半透明側欄** | 可開關、可捲動，顯示說話者及已讀文字，不遮住主要角色。 |
| 重玩存檔 | **與主線隔離** | 重玩章節／回看內容使用獨立狀態，不覆蓋主線自動存檔或手動存檔。 |
| BGM | **依場景切換** | 場景／章節可指定 BGM；音樂與音效音量分開調整，切換柔和淡入淡出。 |

## 5. 執行順序與工作規則

### 建議執行順序

1. 先盤點 8 張角色圖，確認基礎立繪及表情差分。
2. 再盤點 13 張背景圖，完成場景分類與章節映射。
3. 將正式美術接入遊戲，完成角色及背景的視覺驗收。
4. 整理遊戲 UI，完成逐字顯示、對話紀錄與選項互動。
5. 升級多欄位存檔、設定及章節重玩隔離。
6. 製作場景 BGM 配置及音效。
7. 完成成年篇三條路線與全篇劇情審校。
8. 進行手機／桌面完整 QA，修正後發布。

### 每次迭代規則

- 先讀取本文件與 `knowledge/experience.md`，以最靠前且不受阻塞的未完成項目開始。
- 完成後立即更新本文件勾選狀態、`knowledge/experience.md` 經驗，以及必要的素材清冊／決策紀錄。
- 實作完成不等於驗收完成；需經程式檢查或實際遊玩才勾選驗收項目。
- 不因美術尚未完成而停止可獨立進行的故事、UI 或測試工作。
- 修改遊戲資料時執行 `scripts/validate-game-data.js`；推送後確認 GitHub Actions／Pages 部署結果。
- 任何重大設定若與本文件衝突，先更新決策紀錄，再同步更新本文件。
