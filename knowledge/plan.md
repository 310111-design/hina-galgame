# 空崎陽奈二創 Galgame 計畫

## 願景

創作一部以《蔚藍檔案》空崎陽奈為主角的長篇二創戀愛 Galgame。作品以甜甜的日常和酸甜青春感為基調，透過細膩的環境描寫、人物神情與動作、自然對話和選擇分支，呈現陽奈在忙碌日常中的疲憊、放鬆、信任與情感變化。

成品預期採傳統 Galgame 的圖文敘事方式：場景背景、角色立繪與表情差分、必要時的事件 CG，搭配對話框、場景／音樂／音效提示，以及章節結尾的玩家選項。故事與圖像都依情節逐步迭代製作。

## 目標規模與節奏

- **全篇字數：** 約 8 萬～15 萬字。
- **全篇旁白／對話句數：** 約 3,000～5,000 句。
- **單次互動／小節：** 約 2,500～4,000 字，目標約 80～130 句旁白與對話，閱讀時間約 8～12 分鐘。
- 以聊天方式逐節推進；每節按情節提供分支選項，選擇影響後續事件、角色互動及路線發展。
- 篇幅、句數與閱讀時間是整體目標，實際可隨劇情節奏調整。

## 敘事與呈現原則

- 以使用者提供的風紀委員會辦公室片段作為文風與開場參考：夕陽透過百葉窗、堆積的公文、疲憊小憩的陽奈、老師帶來熱飲，以及可供選擇的行動。
- 保留細膩的氛圍描寫、角色表情和動作、克制而有溫度的對話，以及節末互動選項。
- 劇情基調為甜蜜日常與酸甜青春的結合；整體情緒溫暖，容納適度的疲憊、煩惱和心事。
- 以傳統 Galgame 的文字標記呈現背景、BGM、音效、角色立繪／表情、對話與選項。圖像依情境製作，可包含背景、立繪、表情差分和事件 CG。
- 玩家視角與老師角色沿用參考片段作為目前構想；正式戀愛路線的關係設定與界線，待正式迭代時一併確認。
- 目前只規劃作品，不預設使用特定遊戲引擎或製作工具。

## 一、改版總願景

將目前的文字劇情網頁逐步升級為以空崎陽奈為核心、具備沉浸式場景、角色表演、分支劇情與完整閱讀管理功能的視覺小說（Visual Novel）。

核心體驗原則：

1. **遊戲優先：** 開啟遊戲後，主要視覺焦點是背景、角色與對話，而不是一般網站導覽或文章版面。
2. **角色優先：** 陽奈是畫面主角，使用完整 2D 立繪及表情差分呈現情緒。
3. **場景有變化：** 依章節及劇情地點使用有氣氛的專屬背景，避免長時間重複單調佈景。
4. **閱讀流暢：** 點擊遊戲主要區域即可推進對話，操作在手機與電腦上都直覺。
5. **選擇有延續性：** 保留原有選項、分支、條件對話與旗標，讓先前選擇能影響後續故事。
6. **進度可掌握：** 玩家可自由選章節，並使用自動存檔及手動存檔管理進度。
7. **可持續擴充：** 劇情、背景、角色立繪、表情、音樂與 UI 設定盡量資料化、模組化，降低新增內容的維護成本。

## 二、已確認的改版規格

以下五項為使用者已明確選定的正式方向：

| 項目 | 已確認選擇 | 實作要求 |
|---|---|---|
| 畫面比例 | **fullscreen** | 遊戲主要畫面以全螢幕沉浸式呈現，避免一般網頁式框架感 |
| 背景更換 | **chapter** | 以章節作為背景配置與切換的主要單位；章節內可再依劇情地點安排必要變化 |
| 章節解鎖 | **all** | 所有章節皆可直接選擇，不要求依序解鎖 |
| 存檔方式 | **both** | 同時提供自動存檔與玩家手動存檔 |
| 裝置介面 | **adaptive** | 手機、平板、桌面尺寸皆需自適應排版與操作 |

## 三、完整願景與功能清單

### A. 遊戲畫面與操作

- [ ] **全螢幕沉浸式畫面：** 背景鋪滿遊戲視窗，減少網站框架與非必要裝飾。
- [ ] **背景＋角色＋對話框主構圖：** 主要畫面由場景背景、清晰的角色立繪及底部對話框構成。
- [ ] **半透明黑色對話框：** 對話框位於畫面下方，能清楚閱讀文字，同時保留背景氛圍。
- [ ] **角色名稱與文字層級：** 清楚區分說話者、對話文字、旁白及選項。
- [ ] **全區域點擊推進：** 點擊遊戲主要區域空白處即可繼續，不再依賴固定的「點一下繼續」按鈕。
- [ ] **操作優先順序：** 逐字文字尚未完成時，點擊先顯示完整句；有選項或按鈕時，互動控制優先，不得誤觸推進。
- [ ] **鍵盤操作：** 保留 Enter、空白鍵及方向鍵等適合的桌面操作。
- [ ] **場景轉場：** 背景、角色進出場與表情切換採柔和淡入淡出或適度動畫，避免突兀跳切。
- [ ] **自適應版面：** 依手機直向、平板及桌面寬螢幕調整角色尺寸、位置、文字區域及控制項。
- [ ] **可讀性與無障礙基本檢查：** 確保文字大小、對比、觸控範圍與長文字換行合理。

### B. 背景與場景美術

- [ ] **製作專屬背景插畫：** 以遊戲劇情地點製作背景，不再長期依賴單調 CSS 場景或暫定圖形。
- [ ] **章節背景配置：** 每章至少有明確的主要場景視覺；必要時同章依地點或時間切換。
- [ ] **場景類型規劃：** 包含但不限於風紀委員會辦公室、學園教室、走廊、天台、校園戶外及成年篇咖啡店等劇情需要的地點。
- [ ] **背景景深處理：** 背景可輕微模糊、降低對比或柔化細節，讓角色立繪成為視覺焦點；模糊程度不得影響場景辨識。
- [ ] **光線與氣氛差異：** 依時間、天氣、情緒與章節主題安排色調和光影。
- [ ] **背景素材管理：** 使用明確的檔名、尺寸、用途與章節／場景對應表，避免重複及錯配。
- [ ] **素材回退機制：** 缺少背景素材時仍可安全顯示備用場景，不讓遊戲中斷。

### C. 陽奈角色立繪與表演

- [ ] **正式 2D 立繪：** 以使用者提供的陽奈參考圖作為外觀依據，取代拼圖式或暫定 SVG 角色。
- [ ] **外觀一致性：** 保留白色長髮、紫色眼睛、黑色角與紫黑色光環、金色髮飾及風紀委員會制服等辨識特徵。
- [ ] **表情差分：** 規劃平靜、生氣、害羞、困惑、難過、無奈、驚訝、尷尬、傻眼及思考等常用表情。
- [ ] **劇情表情對應：** 對話資料可指定角色表情，並在播放時切換正確素材。
- [ ] **角色動態（分階段）：** 視素材與效能加入眨眼、呼吸、輕微晃動、表情轉場及淡入淡出。
- [ ] **角色素材回退：** 某個表情缺圖時使用預設立繪，不得出現破圖或空白角色。
- [ ] **參考素材核對：** 實際製作前檢視使用者上傳的原始參考圖，逐一確認圖片與表情描述的對應，不可只憑檔名推斷。

### D. 章節、劇情與分支

- [x] **保留既有可玩劇情資料：** 目前專案紀錄已有序章 P01～P03 與 A01～D07 的 30 節可玩內容；後續改版須以現有資料為基礎，不可因 UI 重製而遺失。
- [ ] **章節選擇畫廊：** 提供所有章節的選擇介面，顯示章節標題、簡介及必要的封面／代表背景。
- [ ] **所有章節可進入：** 不以閱讀進度鎖住章節；新玩家也能自由選擇任一章。
- [ ] **章節閱讀狀態：** 顯示未讀、閱讀中、已讀及最近閱讀位置等狀態（狀態定義需一致）。
- [ ] **繼續閱讀入口：** 提供繼續上次進度的明確入口，同時保留自由選章節功能。
- [ ] **章節重新開始：** 可從所選章節開頭開始，不必從第一章重新遊玩。
- [ ] **保留分支與旗標：** 延續既有選項、分支、條件對話及跨章節旗標。
- [ ] **分支驗收：** 檢查不同選擇是否正確影響後續台詞、狀態與結局條件。
- [ ] **章節內場景資料化：** 對話或章節資料可指定場景，不將背景路徑硬寫在大量 UI 邏輯中。

### E. 存檔、讀取與重玩

- [ ] **自動存檔：** 在對話推進、選項完成及章節切換等安全時機記錄進度。
- [ ] **手動存檔：** 提供玩家可辨識的存檔欄位與存檔操作。
- [ ] **手動讀檔：** 可查看存檔資訊並載入指定存檔。
- [ ] **存檔資訊：** 至少記錄章節、對話位置、時間及必要的劇情旗標。
- [ ] **多存檔欄位：** 避免單一進度覆蓋所有遊玩紀錄。
- [ ] **舊版存檔遷移：** 新版讀取舊版資料時保留可相容資訊，遇到不相容資料需安全回退並提示。
- [ ] **存檔版本管理：** 為存檔資料加入版本識別與必要的轉換機制。
- [ ] **重玩隔離策略（待確認）：** 建議重玩章節使用獨立的臨時／新存檔狀態，不覆蓋主要進度；最終規則待使用者確認。
- [ ] **旗標沿用選擇（待確認）：** 重玩章節時需決定沿用目前旗標、使用章節入口預設旗標，或讓玩家選擇；不可默默改寫主存檔。

- [ ] **逐字顯示（待確認）：** 建議逐字呈現文字，玩家點擊可立即顯示完整句。
- [ ] **自動播放（待確認）：** 可選擇自動推進對話，並能隨時暫停。
- [ ] **文字速度設定（待確認）：** 可調整逐字速度。
- [ ] **已讀跳過（待確認）：** 提供跳過已讀文字的功能，並避免意外略過尚未閱讀內容。
- [ ] **快速存讀操作：** 在不遮擋主要畫面的前提下提供容易使用的入口。

## 六、尚待使用者確認的非阻塞事項

以下不影響先進行核心畫面與架構工作，但實作到相應階段前應確認：

1. **背景音樂：** 建議依場景切換氣氛音樂；也可只在重要劇情播放，或維持安靜閱讀。
2. **文字呈現：** 建議逐字顯示，點擊時立即顯示完整句；也可改為每句直接完整顯示。
3. **選項呈現：** 建議直接顯示在底部對話框內；另一方案為畫面中央浮出。
4. **對話紀錄：** 建議半透明側邊面板；另一方案為獨立全螢幕頁面。
5. **重玩章節的旗標與存檔：** 建議使用獨立重玩狀態，不覆蓋主要存檔；仍需確認重玩時是否沿用目前旗標。

## 七、執行優先順序與原則

- 優先完成階段 0～2，先確認現況、建立穩定畫面骨架及背景系統。
- 隨後完成階段 3～5，讓角色演出、自由選章與雙存檔成為可用功能。
- 階段 6 的便利功能與音訊擴充可在核心體驗穩定後加入。
- 最後以階段 7 完成全篇整合、相容性與實際部署驗收。
- 每完成一項功能，必須同時更新本計畫 checklist、相關經驗紀錄及必要的決策紀錄。
- 不可將「已規劃」、「素材已上傳」或「程式已寫」直接視為「已完成」；必須以可執行、可測試且驗收通過為完成標準。
- 未完成的非阻塞項目應持續推進；遇到需要使用者決定的事項，記錄推薦方案與原因，先繼續其他不受影響的工作。
