### 願景

把目前可遊玩的互動故事，持續完成為一部以空崎陽奈為核心、可在桌面與手機舒適遊玩的長篇 Galgame。作品以校園日常和成年後重逢為主線，讓玩家的選擇帶來可辨認的事件差異，並在成年篇明確選擇朋友、搭檔或戀愛關係。最終品質目標涵蓋故事、角色表演、18 張事件 CG、場景美術、介面、音訊、可讀性與跨裝置可靠度；同人創作不宣稱為官方正史。

新增背景、角色圖與事件 CG 以 AI 製作為主。先完成背景、CG、成年立繪各一組代表素材並人工檢視；未達品質門檻時保留現有素材或佔位，不把低品質圖標成完成。作品參考商業 Galgame 的配色、光線、構圖與情緒節奏，不重現其受保護內容。詳見 D-29 及 `knowledge/reviews/commercial-visual-novel-research.md`。

### 美術素材製作與品質分工

- **素材來源：** 角色立繪、表情差分、背景及事件 CG 以可用的 AI 生成工具為主；在本作風格與品質規格內生成、迭代與驗收。不得仿作特定在世藝術家，也不得直接重現商業作品的角色畫面、構圖、標誌、UI 或 CG。
- **未達品質門檻：** 若生成能力不可用，或素材在角色一致性、構圖、文字／解剖錯誤、場景適配等方面未通過人工檢視，保留現有素材或佔位並記錄缺口，不把低品質產物標為完成；不以委託或其他新增來源自動替代。CLI／API 等需金鑰的路徑仍依 D-26 的工具與授權規則處理。
- **來源與版本保護：** 不覆蓋使用者提供的原始素材。為 AI 輸出保留高解析母檔，另產生 runtime WebP；清冊記錄用途、工具／模型版本、提示詞、參考來源、日期、版本與驗收狀態。
- **事件 CG 數量：** 目標為 18 張：6 張共通關鍵場景，以及朋友、搭檔、戀愛線各 4 張。以劇情轉折與關係進展選圖，不為達數量灌水。

### 美術長期目標與具體規格

- **視覺方向：** 延續乾淨的動畫插畫、柔和材質光與金紫色系。校園篇以溫暖夕色呈現青春日常；成年篇以咖啡店暖光、雨夜冷色等環境差異呈現生活階段轉變。現有暗紫金邊 UI 維持可讀、可操作，不把文字或控制烘焙進背景圖。
- **背景與 CG 母檔：** 新製作場景底圖與全螢幕事件 CG 使用 16:9、至少 1920×1080 的母檔；重要視線焦點放在角色立繪及底部對話區不會遮住的位置。背景不得含人物、UI、標誌、浮水印或不可讀假字；runtime 另輸出最佳化 WebP。既有低解析素材保留並記錄差距，不因新標準覆寫原圖。
- **角色立繪：** 保留目前 13 張使用者提供的 896×1200 表情原圖不變。後續透明 sprite 以 896×1200 runtime 畫布為相容基準，保持臉型、髮色、光環、服裝、比例、鏡頭與站姿一致；差分只改劇情需要的表情。成年篇另建立身分與服裝明確成年的陽奈立繪，維持角色辨識度。
- **CG 場景配置：** 6 張共通候選聚焦初期相處（P01）、建立合作（B02）、自主休息（B08）、校園告別（C06）、成年重逢（D01）及成年後關係選擇（D06）。三線各 4 張分別涵蓋朋友日常、平等合作與戀愛雙向選擇；每張須呈現獨特情節，景別包含環境建立、人物互動及情緒近景等變化。
- **人工品質檢視：** 檢查人物辨識度、表情／服裝連續性、手部與配件、透視、光影、場景道具、透明邊緣、假字及壓縮瑕疵；CG 不得讓 UI 遮住表情或重要動作。每批先製作背景、CG、成年立繪代表樣本並檢視，再擴大生成。
- **跨裝置驗收：** 桌面 1440×900、手機直向 390×844、手機橫向 844×390 都要檢查構圖裁切、對話文字安全區及 UI 遮擋；另安排 iPhone Safari 實機驗收。模擬 viewport 或資源 HTTP 200 不能代替實機驗收。

### 目前最重要的缺口

## 1. 最終願景

### 1.1 玩家體驗

- 開啟作品後直接進入 Galgame 遊戲體驗，而不是只看到企劃文件或展示頁。
- 畫面以場景背景、陽奈立繪及底部對話框構成；場景依章節與劇情地點變化。
- 角色在對話中能以表情、姿勢與事件 CG 呈現情緒和劇情重點。
- 對話逐字顯示；點擊時先補完目前句子，再次點擊才前進。
- 玩家可點擊舞台空白處推進；選項、按鈕、選單與紀錄操作不得誤觸推進。
- 選項能影響後續對話、共同回憶、事件或關係路線，避免只有文字不同的假選擇。
- 可使用章節選擇、對話紀錄、已讀跳過、自動播放、速度／字體設定、存檔／讀檔及音量設定。
- 手機直向、手機橫向、平板與桌面皆能清楚閱讀及操作。

### 1.2 故事願景

- **基調：** 甜甜日常 × 酸甜青春；以環境細節、自然對話、角色神情及生活互動建立情感。
- **校園篇：** 著重信任、照顧、合作與逐漸理解；不將校園時期的師生互動直接定義為戀愛。
- **成年篇：** 暫定學生時代結束五年後，於車站附近的獨立咖啡店重逢；雙方已無師生／指導權責，以平等且自主的成年人身分重新認識彼此。這是本同人作品的創作設定，不代表官方正史。
- **三條成年關係路線：**
  - **朋友線 D08F：** 保留深厚信任，成為能自在分享生活的朋友。
  - **搭檔線 D08P：** 互相支持、共同完成目標，尊重彼此專長與責任界線。
  - **戀愛線 D08R：** 成年後逐步確認感情，建立雙向、自主且平等的關係。
- 校園篇選擇可影響成年篇的共同回憶、熟悉程度及對話細節；正式關係由成年篇玩家明確選擇，不由隱藏分數自動決定。
- 三條路線應各自有專屬事件、關鍵對話與結局，而非只替換結尾段落。

### 1.3 篇幅目標

- 全篇唯一正文長期目標：約 **80,000～150,000 字元**；2026-11-26 B08 場景連續性複核後依目前 runtime 台詞文字去重為 **73,990 字元**。
- 全篇旁白／對話句數長期目標：約 **3,000～5,000 句**。
- 單節參考目標：約 **2,500～4,000 字、80～130 句、8～12 分鐘閱讀**。
- 共通段落只計一次；互斥分支各自計入全篇唯一正文總量；另估算單次完整遊玩的實際閱讀量，兩者不可混為一談。
- 目前 33 個章節節點、3,267 條對話 tuple（含 21 組條件對話）；所有可能分支及條件台詞共 74,779 字元，去除完全重複台詞後為 74,135 字元／3,177 條唯一台詞文字；21 組條件台詞合計 704 字元。
- 純文字閱讀時間仍無玩家計時，以 300～400 字元／分鐘作明示估算假設：單一路線 55,394～56,672 字元，約 **2.3～3.1 小時**；把全部分支及條件對話各看一次、跳過重複共通段，74,779 字元約 **3.1～4.2 小時**；三條成年路線都從頭重讀、不跳過重複共通段，約 **167,956～168,292 字元／7～9.3 小時**（此重讀模型不含條件對話）。不含選項操作、讀檔、動畫停留或玩家停頓；速率為估算假設，並非實測。計算依據見 `knowledge/reviews/playtime-estimate.md`。
- 篇幅是規劃指標，不得為湊數灌水；角色一致性、節奏與選項品質優先。

本專案不以完成目前清單或維持既有架構為最終目的。路線圖是當前最佳工作假設，應持續依作品品質、實際測試、研究與製作經驗修正。

#### UI 2.0 設計原則

1. **角色優先，功能退後：** 角色臉部、表情及重要裝飾不得被對話框遮住；主要視線先落在場景與角色，再落在文字。
2. **演出區最大化：** 頂部狀態資訊低存在感，次要工具預設收納；保留必要操作的可發現性與觸控可用性。
3. **一般對話與選項分離：** 一般對話採姓名牌＋對話文字；只有需要玩家決策時才切換選項呈現。
4. **選項清楚但不厚重：** 以間距、細線、選取高亮與字級建立層級；「影響」等輔助資訊降階呈現，不與選項主文競爭。
5. **背景保留場景資訊：** 依場景設定柔焦／暗化／漸層；對話可讀性優先，但不能讓背景細節全部消失。
6. **延續既有規格：** fullscreen、chapter 背景切換、all 章節解鎖、both 存檔及 adaptive 裝置策略維持不變；手機直向仍以易點擊的直列選項為主。
7. **可回退與漸進修改：** 優先以 CSS 變數、元件樣式及小範圍 HTML 調整完成；不重寫劇情引擎，不破壞存檔格式、選項資料或既有鍵盤／觸控操作。

#### 建議版面架構

- **頂部資訊區：** 保留作品／章節／進度等必要資訊；將章節、紀錄、存檔、讀檔、重來、設定等功能整併至單一選單或分組面板，避免六個同權重按鈕長期常駐。全螢幕控制保留在可找到的位置。
- **主要演出區：** 背景、角色立繪及表情差分為主。角色整體上移並依手機直向／橫向／桌面分別調整尺寸與錨點；對話框上緣不得切過臉部、眼睛或關鍵裝飾。
- **一般對話區：** 底部半透明對話面板，清楚呈現角色姓名牌與正文；自動播放、快進等控制以小型輔助操作呈現，不與正文搶視線。
- **選項區：** 沿用底部對話區的視覺語言，三選項在手機直向垂直排列；透過選取高亮、焦點狀態及適度動畫表達互動，不把選項做成厚重表單卡。
- **輔助功能區：** 紀錄、章節、存讀檔、設定等採可開關面板；開啟時需避免誤觸舞台推進，關閉後回到原閱讀狀態。

## 6. 每次迭代工作規則

- 開始前讀取本文件、`knowledge/experience.md`、`knowledge/decision.md`，並檢查 GitHub main 最新 commit、工作目錄及 Actions 狀態。根目錄 `decision.md` 不存在時，以實際的 `knowledge/decision.md` 為準。
- 只從本文件尚未完成且不受阻塞的最前面項目開始；不要重做已完成工作。
- 完成一個階段後更新本文件勾選狀態，並將可重用經驗及適用範圍回流到 `knowledge/experience.md`。
- 經驗補記 `knowledge/experience-early-act-transitions.md`、`experience-prologue-transitions.md`、`experience-first-act-opening.md`、`experience-first-act-middle.md`、`experience-first-act-ending.md`、第二幕各批補記及第三幕／成年篇補記的可複用方法、限制與適用範圍均已合併至 `knowledge/experience.md`；原補記保留為詳情來源。追加前先對照主檔，避免把同一經驗重複匯入；歷史工具阻塞文字以目前主路線圖及 repo 可驗證狀態為準。
- 階段變更單若已合併主計畫，需在檔首標示歷史狀態與現況連結；保留舊檢查清單作追溯證據，但不可讓過期方框冒充目前 TODO。
- 重大設計決策或暫停／恢復狀態變更時，同步更新 `knowledge/decision.md`。
- 程式已接入不等於驗收完成；只有實際測試完成才勾選實機 QA。
- 修改遊戲資料時執行 `scripts/validate-game-data.js`；有對應檢查時一併執行素材與路線驗證。
- 每次 push 後以 GitHub Actions REST API 查最新 workflow run；成功後再確認 Pages 部署結果。若 API 不可用，明說尚未確認，不將固定 validator 成功混同部署成功。
- 美術素材依本文件「美術素材製作與品質分工」執行：先實測可用能力與品質；達標才生成／處理並驗收，不達標就保留佔位並記錄需求，不得將低品質素材冒充正式成果。
- 圖像／美術相關工作須獨立列項、獨立回報，說明素材或圖號、接入狀態與待辦；不可和劇情、程式或其他工作合併成同一段進度回報。
- 若某項需要使用者偏好或外部素材，記錄阻塞原因與推薦方案，繼續其他可獨立完成的工作。
- 每階段以一至兩句中文回報成果，再繼續下一個可執行階段。
