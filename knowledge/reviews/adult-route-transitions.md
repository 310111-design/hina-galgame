# 成年篇後段 D05→D06→D07：邀請答覆與路線交接審校

## 範圍與結論

完整閱讀 `story/chapters/D05.md`、`D06.md`、`D07.md`、`D08F.md`、`D08P.md`、`D08R.md` 與 runtime 對應資料及 `knowledge/chapter-plan.md`。人工核對 D05 A／B／C 到 D06 的九種入口組合，以及 D06 三種路線選擇到 D07 三種活動選擇的九種組合；另確認 D07 結尾的路線目標與三個結局節點一致。不是 18 次瀏覽器通關或全史旗標窮舉。

- D05 A／B／C 分別談現在的彼此、學生時代想保留的感覺與不急著定義關係；三路徑均合流後由陽奈提出下週到住處喝茶的邀請。
- 原稿說明玩家可以回去考慮，且陽奈不追問答覆；D06 卻直接確認已排好的時間並描寫玩家到達住處，缺少中間接受邀請的事件。
- D06 A／B／C 分別選朋友、搭檔、戀愛方向，寫入 `friend`／`partner`／`romance` 路線；common 只談可以協商的相處原則，不把戀愛方向當成已交往。
- D06 結尾提出下次可在其他地方見面；D07 以訊息邀請河邊相處，沒有預設 D06 的關係路線或必須同意邀請。
- D07 A／B／C 分別去咖啡店、留在河邊或讓陽奈安排最後十分鐘；common 接收三種活動，之後依 D06 留存的路線分流至 D08F／D08P／D08R。

## DART 發現與修訂

### DART-01｜到訪前需呈現玩家接受邀請（已修）

- **證據：** D05 將答覆留到之後，D06 卻從已確認時間開始，沒有交代玩家是否接受住處邀請。
- **修訂：** D05 結尾補上回家後玩家傳訊息接受下週喝茶，同時保留不自在時改到公共場所的選擇；D06 開場改為確認談妥的時間，不再次提出邀請。

### DART-02｜關係路線與當次活動選擇需分開（核對通過）

- D06 的三個選項各自寫入一條成年關係路線；D07 的三個選項只改變當日活動。D07 common 沒有把活動選擇解讀成關係選擇或重新設定 route。

### DART-03｜結局出口須保留 D06 路線狀態（核對通過）

- `D07.nextByRoute` 對應 `friend → D08F`、`partner → D08P`、`romance → D08R`；三個目標節點 ID 存在，結局各自維持朋友、搭檔與戀愛內容。
