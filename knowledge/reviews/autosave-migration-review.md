# 自動存檔與手動讀檔版本隔離修正

日期：2026-11-24  
範圍：自動存檔版本標記與章節索引遷移；連同前一階段手動存檔舊索引修正檢查。未執行真實瀏覽器點擊流程。

## 發現與修正

手動讀檔會把遊戲狀態標為 v3，但一般 `saveState()` 直接序列化同一個狀態至自動存檔鍵。重新載入時，舊 `loadState()` 只把目前鍵的 v2 判定為已含序章索引，其餘格式一律加三章；因此讀入手動存檔後重新載入，可能錯移章節。未知未來版本也可能被錯判為舊版。

現以儲存鍵和已知版本共同決定索引：舊存檔鍵中無版本欄位的資料加 3；目前鍵的 v2 與曾由手動讀檔寫入的 v3 均不位移；目前鍵的未知版本與未版本化資料回到預設進度，不套用猜測性遷移。自動存檔寫入時強制保存為 v2，避免手動存檔版本外洩到自動鍵。

同時補上存檔保護：若目前自動存檔格式未知、JSON 損壞、既有鍵含 null／陣列等非存檔值、讀取失敗，或保存階段欄位無效，遊戲仍可用預設狀態開始，但停用自動寫入並顯示原因，避免預設進度蓋掉玩家原始資料。玩家明確確認重新開始，或成功讀取有效手動存檔後，才解除保護並恢復自動寫入。

## 回歸檢查與限制

- `scripts/validate-autosave-migration.js` 使用實際 runtime 的 offset、載入、保存、重開與手動讀檔函式和記憶體 localStorage，確認舊鍵遷移、目前 v2／v3 章節索引、v3 狀態寫入自動鍵時正規化為 v2、未知版本／未版本化資料／無效階段／損壞 JSON／null 與其他非物件值／localStorage 讀取失敗的預設回退及寫入封鎖、原始資料不被覆寫，以及明確重新開始或讀取有效手動存檔解除封鎖。
- `scripts/validate-manual-save-migration.js` 繼續確認單格舊存檔與已存在六格資料的逐格遷移、版本守衛及冪等性。路線、資料、篇幅、序章、殼層、素材與 JavaScript 檢查一併執行。
- 這些是 runtime 函式的記憶體情境測試，不能取代真實瀏覽器儲存、手動存讀互動或重載後保持章節的驗收；Phase 4 的實機存檔 QA 維持未完成。

## 可複用範圍

互動作品若手動與自動存檔共用同一進度物件，載入一種格式後應在寫入另一種格式前正規化版本。遷移時同時檢查資料來源鍵、明確版本與章節索引；未知版本保留既有資料並安全回退，不套用預設位移。適用於本作序章新增後的索引調整，也適用於未來章節順序變更及其他依陣列位置保存進度的遊戲。
