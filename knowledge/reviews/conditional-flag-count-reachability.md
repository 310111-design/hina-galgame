# 條件回憶旗標累積門檻可達性複核

日期：2026-11-24  
範圍：33 個 runtime 章節、21 組 `flaggedIntro` 回憶條件，以及選項旗標與 A06 固定 `daily_checkin` 增量。此複核補足既有「至少有足夠不同章節提供旗標」檢查，確認實際遊玩可累積到每組條件的數值門檻。

## 發現與驗證

原有旗標可達性檢查確認來源章節數，卻沒有直接比較每組條件的 `min` 與前序流程可能累積的最大次數。新增 `maximumReachableCounts` 推導：每個前序非結局章只計入玩家能選到的旗標種類一次；另計入 A06 每種選擇都會觸發的固定 `daily_checkin` 增量。D08F／D08P／D08R 是互斥終點，不把其選項輸出傳遞至兄弟結局。

驗證器在每個章節入口先檢查 `flaggedIntro` 門檻，再累加當章可選旗標與引擎固定增量。旗標種類的可達性仍由各章稿入口與節末摘要對照檢查；實際 runtime 每個選項如何增量、A06 固定增量、條件台詞低於／達到門檻的顯示，以及三個結局路由，則由 `validate-choice-runtime.js` 覆核。

21 組條件均可達。代表性最大次數：P03 的 `rest`／`teamwork`／`ordinary_day` 各為 2；B01 的 `daily_checkin` 為 2（包含 A06 固定增量）；C01／D01 的 `self_rest` 為 1；三個 D08 結局入口的 `rest`／`teamwork`／`ordinary_day` 分別可達 27／26／27。這些是可選路徑的上限，不代表一般玩家必然選出該組合。

## 限制

- 計數推導依據是每節皆可選其三個選項、每章線性前進，以及遊戲資料所列的選項旗標；目前不存在依先前選項鎖定後續選項的規則。新增選項鎖定、跳章或額外旗標寫入時，必須擴充此模型。
- 此檢查確認每個單獨條件可以達標，不窮舉所有跨旗標向量、存檔匯入歷史或玩家實際瀏覽器操作。
- 固定驗證通過不等於玩家能在 UI 中辨識條件回憶，也不代表全篇逐路通關、盲讀或實機 QA。

## 可複用範圍

本作條件回憶、跨章累積旗標及三個互斥結局；也適用於任務樹、對話狀態機與表單流程中的數值門檻。當一個狀態能在多個前序節點累積時，應把「曾出現此狀態」與「實際數值可達門檻」分開驗證，並納入引擎固定增量和互斥終點邊界。
