# 序章與前兩幕交界：人工文本審校紀錄

## 階段與結論

- **本階段交付：** 一批獨立的人工文本審校；不是修訂交付、全篇審校通過或實機 QA。
- **完整閱讀的章稿：** `story/chapters/P03.md`、`A01.md`、`A06.md`、`B01.md`。檢查各章 intro、A／B／C 分支、共通收束，聚焦 P03→A01、A06→B01。
- **補充依據：** `knowledge/flag-dialogue.md`；`site/game-data.js` 工具回傳範圍內的 P02、P03、A01；三個固定 validator 的執行結果。P02 僅用於確認到訪時間，不宣稱整章另完成審校。
- **結果：** 發現下列連貫性與敘事語氣問題；全部保留待修，未修改劇情稿或 runtime，故本次未製造新的稿件／runtime 差異。
- **審查方法：** 對兩個交界各以三種前章出口×三種後章分支，人工核對九種組合的必要前提（共十八種局部組合）；這不是十八次瀏覽器通關，也不枚舉前面所有旗標歷史。另以明確反例檢查無 teamwork 的路徑。

## 發現與推薦修訂

### EAT-01｜A01 到訪次數沿用序章未接入前的敘述（待修）

- **證據：** P02 runtime 開場已是「隔天放學鈴響起時」且陽奈說「老師，你又來了」。P03 共通承接「明天放學」。A01 標題、第一句「第二次走進風紀委員會辦公室時」及 common「第二次放學後並沒有帶來重大變化」仍限定第二次。
- **影響：** 不論 P03 選 A／B／C，前面至少已有 P01、P02 兩次到訪，A01 的次數敘述不成立。
- **推薦：** A01 改用「再次放學後」或「又一個放學後」，首句「再次走進……」，common 同步去掉固定次數；同步 runtime title、intro、common 與 P03 節末、章節卡等名稱引用。不要機械替換成第三次，以免未來插章又失效。

### EAT-02｜A01 B 分支把可選分工回憶寫成必然（待修）

- **證據：** A01 B 台詞「這就是昨天下午我們說的分工？」在 Markdown 與已讀 runtime 都存在。P03 只有 B 明確討論分工，`teamwork >= 1` 的回收亦是條件段。
- **反例：** P01=A、P02=A、P03=A（或 C）→A01=B；此前可沒有任何 teamwork 選擇，P03 teamwork 條件回憶也不會出現。
- **推薦：** 將 A01 B 改為當場確認「這樣就能分清楚判斷和整理？」之類不要求昨天事件的台詞；保留當前玩家選 B 帶來的實際分工，不增加新旗標或強制回憶。

### EAT-03｜P03 未定約的出口與 A01 精確約定時間（待釐清）

- **證據：** P03 intro 未確定下次地點，common 明言沒有保證一定來找你；A01 卻說「今天來得比約定時間早兩分鐘」。
- **判定：** 可以用章間另行聯絡解釋，但目前文本沒有交代，不列為無法成立的硬矛盾。
- **推薦：** A01 開場補一句「今天稍早確認了放學後見面」；保留 P03 可重新協商的主動權，不把所有分支改成必須每天赴約。

### EAT-04｜A06 多次離場與燈光狀態回跳（待修）

- **證據（章稿 common）：** 「你們離開辦公室時，桌燈熄滅」後又有「陽奈推開門後」、「陽奈關上辦公室的門，桌燈熄滅前仍照著便條」，走廊最後一扇門關閉後更寫「辦公室裡只剩便條被桌燈照亮」。抵達校舍出口後仍反覆描述離開／推門。
- **物件：** 便條先夾在公文夾上方、文件夾收起，後來卻寫「便條沒有被放在公文夾最上面」，缺少取下放回桌角的動作。
- **影響：** 共通段缺陷，A／B／C 都受影響；不應藉新增分支轉場掩蓋共通狀態錯誤。
- **推薦：** 整併為單一路徑「收妥文件→將便條留桌角→熄燈離室→穿過走廊→離開校舍」。收束後若要回看便條，以記憶或翌日開場呈現。先修動作順序，再重算篇幅；不得為維持字數保留重複告別。

### EAT-05｜A06 角色語氣及次日指涉（待修）

- **證據：** 陽奈直接說「第一幕裡，我一直在問自己是不是能交出去工作」，將章幕編排說成角色可知資訊。另有「如果明天太忙，十分鐘也可以改成明天的十分鐘」的同日反覆，以及 B 選項「明天先看分工清單，再決定今天剩多少」的時間主詞跳動。
- **推薦：** 角色台詞改為「這幾天」；重新安排的十分鐘改為「另找一個明確的時段」；B 選項改「確認當天能留多少時間」。敘述中的「第一幕／明天的劇情」也建議轉為角色生活中的日常語彙，保留幕次只在章節標題／節末 metadata。

### EAT-06｜B01 C 的已逝時段與工作量判斷（待修）

- **證據（章稿）：** 開場已在放學後、明確工作量增加約三成，C 卻把「今日任務」排列到「可在放學前完成、放學後確認，以及明天完成」，未區分已做和待做；台詞「原來我以為是工作量增加，其實是時間分配沒有重新確認」又否定 intro 的客觀增加。
- **推薦：** 欄位改為「今天已完成／今晚需確認／可留到明天」，台詞區分「工作確實增加，但不必全擠在放學後」。保留 C 重排時段的獨特結果，不改成 B 的交付事件。

### EAT-07｜B01 A 的『工作之前』含義（待釐清）

- **證據（章稿）：** A 台詞「把十分鐘排在工作之前」，緊接著安排在放學後五十分鐘；intro 已描寫整理與分類工作。
- **判定：** 「先安排休息」與「先實際休息」容易混淆，但文本未提供當下精確鐘點，不斷言五十分鐘已經過去。
- **推薦：** 改為「先把十分鐘排進今天的安排」，或補明下一輪工作開始前休息的時間；保持 A06 預留而非無限延期的主題。

## 可保留的銜接與分支差異

- P03 A／B／C 的局部動作各自成立；共通拿取「十分鐘」便條不必依賴 B 才寫的分工便箋背面。該交界的主要問題在 A01 的回憶前提，而非要求刪掉 P03 分支。
- A01 A 談疲累、B 實際核對回報、C 分享普通小物，未在本批發現三選項只有措辭差異的問題。
- A06 A／B／C 各提出翌日先休息、先核對分工、先做普通事；共同結果是可重複、可調整的保留時間，不是保證每天完美執行。因此 B01 工作增加、再次猶豫分工本身不等於成長倒退。
- B01 的 `daily_checkin >= 1` 回憶只提預留時間，`teamwork >= 2` 回憶只提把可交付確認列入清單，沒有宣稱所有工作已交付，與 intro 的尚未分出去不衝突。固定 game-data 檢查確認該兩組與條件對話文件一致；本工具未回傳 B01 runtime 全文，未聲稱人工逐句比對該節 runtime。
- 沒有改動路線、旗標、存檔格式或背景映射；校園信任與成年篇關係界線維持既有規格。
