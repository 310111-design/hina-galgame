## 發現與推薦（採用為後續修稿基準，未實施）

### AAT-01｜A02 昨日詢問沒有明確文本來源（已修）

- A02 intro：「沒有像昨天那樣問你今天有多少時間」。A01 各路徑均未出現陽奈詢問玩家可用時間；開場只是確認提早兩分鐘，共通是讓她自己想十分鐘用途。
- 可解釋為省略的章間互動，故非硬矛盾；但正文特指昨天，增加不必要的共同回憶假設。
- **推薦：** 改為當下觀察「這次沒有先確認你能停留多久」，不要為填一句回憶新增強制前章事件。A01 已有 EAT 到訪次數／約定時間問題仍由 EAT 處理，不重開完成紀錄。

### AAT-02｜A02 ordinary_day 回憶要求了旗標不能證明的離室事件（已修）

- `ordinary_day >= 1` 顯示：「上次離開辦公室後，你們沒有繼續談公務。今天陽奈也先問起那段普通的時間。」
- **反例（從零旗標連續遊玩）：** P01=B、P02=B、P03=A、A01=B。A02 入口 `teamwork=3, ordinary_day=1, rest=0, daily_checkin=0`。ordinary_day 只來自 P03 A「下次想先決定時間用途」，未建立兩人共同離室、不談公務的實際事件；A01 common 是玩家離去而陽奈留辦公室翻巡邏表。
- A01 C 也只是問陽奈「昨天離開辦公室後」做什麼，答案是她獨自回宿舍整理文件，不是兩人已共同散步。因此即使上一節選 C，也不能直接支持該回憶。
- **推薦：** 同步旗標文件與 runtime 改為「你記得她曾想把一段時間留給公務以外的事。今天，你也沒有急著把話題限定在退件上。」保留 ordinary_day 門檻，不增精確事件旗標、不誤把當章 C 當成觸發歷史。
- `rest >= 1` 的「上次」也可能指較早休息而非緊接的 A01；推薦改「之前」降低最近一次限定。teamwork 回憶只談曾確認過的分工，未要求交付已全部成功，本批未找到同類反例。
- 本批使用必要反例，不宣稱已枚舉 P01～A01 全部 81 種歷史或實測引擎。

### AAT-03｜重做、退件與重新提交的次數口徑（已修）

- A02 intro：「第三次展開」「不是……兩次退件，而是……三次重做」；common：「確定第二次提交是否真的符合規則」「沒有在今晚解決全部退件」。A03 intro：「已經完成第一次重新提交」。
- **判定：** 第二次提交等於第一次重新提交，二者本身一致；三次編修亦可能只源於一次退件。不能把三次重做誤判成三次重新提交。
- **推薦：** 明寫「同一次退件後已反覆改了三遍，尚未重新送出」，common 改為「明天重新提交前再核對一次」，A03 標示「今天放學前已送出修訂版，尚待回覆」。保留 A02 當晚未完成→A03 翌日已提交、但不預設已獲核准的時間線。

### AAT-04｜A02 共通燈光名稱回跳（已修）

- common 先「關上桌燈，但沒有關上文字清單旁的小燈」，之後又「桌燈照著退件表」，未交代重新開燈。
- 可能後句泛指小燈，但讀者會把桌燈當成剛被關掉那一盞。A/B/C 均受影響。
- **推薦：** 後句改為小燈餘光照到退件表，或統一最後才關主桌燈；只選一條明確光源時間線。便條移到公文夾內側有明寫，不因物件換位置再另判矛盾。

### AAT-05｜A03 C 選項說留到明天，實際仍完成今天清單（已修）

- choices C：「把清單留到明天，今天先談它不需要變成正式規定的原因。」分支卻寫「只用於今天放學後」、翻背面補記，共通開頭又「清單完成了」。
- **推薦：** 改選項為「先確認清單只作今天的暫時工具，不急著訂成正式規定。」保留 C 拒絕永久規章的差異，不把 A/B 也改成延後工作；同步 Markdown 選項與 runtime label。既有逐句對照不檢查 choices，因此仍須人工核對 label。

### AAT-06｜A03 欄位從三欄變兩欄／第三欄，缺少重整動作（已修）

- intro 三欄是「資訊、判斷、確認」；B 已移到「可交付欄」但未說何時改欄名；common 先說兩欄（本人判斷／可交付確認），接著第三欄原本是「不需要現在處理」又被畫掉，後面仍要未知項目留在正確欄位。
- **推薦：** intro 三欄只作核對面向；進入分支前明確另畫決策／交付兩欄，資料不足列在下方「等待資訊」區。common 核對這兩欄與等待區，不畫掉未知項目的位置。保留 A 的時間註記、B 的交付箭頭與 C 的暫時用途，避免為修共通段抹平差異。

### AAT-07｜A01 共通送客動作和重複記日期（已修）

- common 先「站起來送你到門口」，緊接推桌角巡邏表，後又「沒有立刻走向門口」；兩次在便條旁寫下「小小的日期」，沒有說第二次是另一日期。
- **推薦：** 統一「準備送客→仍在桌邊交代明日回查→記日期一次→送到門口→玩家離去→陽奈回桌」，後半便條文字另稱註記，不重複寫日期。
- 玩家離去後描述陽奈留室可採鏡頭旁白，不將此形式本身判為錯誤；EAT-04 的 A06 重複離場是另章問題，本項不是前批已修成果。
