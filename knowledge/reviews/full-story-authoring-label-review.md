# 全篇玩家可見章號與幕次編輯語檢查

日期：2026-11-24  
範圍：掃描 `site/game-data.js` 的 intro、分支、common 及條件對話文字；不掃標題、metadata、節末製作記錄和供玩家操作的選項標籤。搜尋精確章節代號（例如 `B05`）及「第一幕／第二幕／第三幕」等作者用結構字樣，再逐句對照章稿、相鄰事件和已審校的時間線。

## 防回歸與驗證

`validate-game-data.js` 現在拒絕劇情台詞中的完整章節代號（P01、A01～D07 等）及中文數字幕次，並帶有正／負 regression fixture。標題、章稿 metadata、節末記錄仍可保留章號，因為它們不是遊戲 runtime 劇情文字。固定 `validate-route-drafts.js` 確認受影響稿件／runtime 與 D06 宣告統計同步；`validate-game-data.js` 確認 33 章、99 選項／分支、21 組條件記憶與幕次／章號規則；`validate-full-length-summary.js` 核對全篇篇幅。

最新篇幅為 3,480 條對話 tuple、原始文字 80,701 字元、精確去重 80,066 字元／3,391 條唯一文字。此為統計更新，並非遊玩計時或全篇敘事品質評分。

## 限制與未來用途

精確代號搜尋能找出明顯的內部章號，不能辨認不含代號的製作語（例如「本節結束」）或其他抽象旁白。逐句仍需對照角色時間線與口吻；若某作品有意讓角色談章節／幕次，應先調整規則範圍，不可只為通過 CI 改寫玩家文字。

未來適用於本作新增劇情或搬移章節時的 runtime 審查；也適用於依章節 ID 組織的視覺小說、任務文本及互動故事，防止內部資料代號混入正式旁白。
