# 六格手動存檔容器保護

日期：2026-11-24  
範圍：`MANUAL_SLOTS_KEY` 容器、舊單格匯入及錯誤時的手動寫入保護。回歸檢查使用記憶體 localStorage，未執行瀏覽器點擊流程。

## 發現與修正

`loadManualSlots()` 原先在槽位 JSON 損壞、localStorage 讀取失敗、頂層不是陣列時回傳六個空欄；超過六格的陣列則取前六格並可能把截短結果存回。合法陣列中的 `false` 等非空無效欄位也可能正規化成空欄，再於別欄存檔時一併覆寫。這些情況可能丟失無法解析的原始值或額外資料。舊單格資料若存在但版本不支援，也沒有明確阻止後續手動寫入。

現在僅在槽位鍵不存在時視為空白存檔。鍵存在但 JSON 損壞、頂層容器格式不支援、陣列超過六格、含非空無效單格、舊版資料無法辨識或 localStorage 讀取失敗時，保留原始值並暫停手動寫入；存檔選單顯示原因，存檔按鈕停用。超額陣列仍提供前六格可辨識存檔的讀取，不會截短寫回。有效且已知的舊版資料仍走既有遷移流程。

## 回歸驗證與限制

`scripts/validate-manual-save-migration.js` 使用 runtime 的實際 `loadManualSlots()`、格式正規化與 `saveManualSlot()` 函式驗證：

- 舊單格 A01／D07、序章後 v2、目前 v3 與未知 v4 行為。
- 損壞 JSON、未知頂層容器、超過六格的陣列、損壞／未知單格及未知 legacy 存檔均保持原始 raw 值。
- localStorage 不可讀時封鎖寫入。
- 對損壞槽位容器呼叫 `saveManualSlot()` 後，原始內容不變。

固定函式檢查不代表瀏覽器存讀對話框、覆蓋確認、空格互動、Safari 儲存權限或 quota 行為已驗收；Phase 4 實機 UI QA 維持未完成。

## 可複用範圍

本作增加存檔格數、變更槽位 key 或加入格式升級時，先分辨鍵不存在、已知舊版、損壞內容與未來容器；未知資料應保留且停止覆寫。此方式也適用於以瀏覽器儲存多筆草稿、設定或離線工作資料的前端應用，避免解析失敗的回退值被當成可安全保存的空資料。
