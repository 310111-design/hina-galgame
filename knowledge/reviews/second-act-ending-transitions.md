## C01 條件回憶前提

條件段位於 intro 之後、選項之前；同步由 game-data 驗證，不混進 routes 的 150 條 C01 正文。

| teamwork >= 2 | self_rest >= 1 | 檢查結果 |
|---|---|---|
| 否 | 否 | 不顯示條件回憶；主線仍須自己交代任務來源，不依賴旗標補前提 |
| 是 | 否 | 「之前一起整理的交付規則」是一般累積回憶，沒有指定必走某個分支；但不能據此證明「昨天離開前」已交付本次任務 |
| 否 | 是 | 行程留白能呼應 B08 所有分支的 self_rest；不要求玩家必選 B 的便條 |
| 是 | 是 | 兩組資訊可以並存，不相互覆蓋；任務條件來源和休息執行仍由正文交代 |

正常主線 B08 三個分支都增加 `self_rest`，因此接 C01 時此條件會命中；未命中情況只作低旗標入口／測試狀態分析，不聲稱重玩 UI 必定清空旗標。`teamwork` 是累積類型，不等同特定任務完成旗標；本次未發現 C01 條件台詞像 AAT 的具體外出回憶那樣必須某條唯一歷史，但也不以此宣稱已窮舉所有過去事件。

## 發現與推薦

### BET-01｜隔日第一輪已完成，但設備回查又推到明日（已修訂）

- **初次判定：** B07 common 預告明天先看回查資料；B08 隔日 intro 說第一輪完成，但 C 分支又寫明日看設備回查，當時缺少既有結果及任務身分。
- **修訂結果：** B08 intro 現明示早上七點收到缺件原始紀錄，按日期與來源完成核對、七點半前完成格式交接，前一晚回查結案。C 分支寫的是「下一項例行任務」的範圍與資料來源；C01 再明確指出今日開始另一項每週工作，兩項新例外不與舊缺件混淆。
- **驗證界線：** 章稿與 runtime 同步及固定檢查可確認文本一致；不代表完整歷史路徑通關。

### BET-02｜分支休息與 17:10 共通起點未對齊（已修訂）

- **初次判定：** 各分支先有散步、喝水或寫備忘，之後 common 才從 17:10 開始；收工時間和預留時段容易被讀成先休息、再起算一次。
- **修訂結果：** B08 intro 將 17:10～17:20 定為唯一不查看訊息時段；A 明寫散步後回到桌邊時尚未到 17:10，C 只在開始前留下明日第一步並停止其他整理。common 以「十七點十分到了」開始固定時段，17:20 後才查看一則普通訊息並結束工作，沒有再安排第二段休息或公務。
- **驗證界線：** 章稿/runtime 同步不等於實際玩家的時間感受或逐路瀏覽器通關。

### BET-03｜A 外出後 common 無回室；容器與位置也要對齊（已修訂）

- **證據：** B08 A 明寫走出辦公室，在販賣機前拿「一罐飲料」後「打開瓶蓋」；common 直接看抽屜、用筆補便條、17:20 開抽屜且「先喝了一口水」。A 未回室，B 喝水而 C 沒有水杯來源；C 分支開頭「回到桌前」前也沒有離桌動作。
- **推薦：** A 選一種容器（推薦瓶裝水，對齊瓶蓋與水），明寫散步後回室，再接 17:20 的共通收尾；共通不在回室前引用抽屜或桌面。B／C 若要共同喝水，需共通新取水杯或改為不依赖特定飲品的動作。C 開頭改為仍在桌前，離桌留給履行選項時發生。
- **邊界：** 「罐」與瓶蓋是物件不一致；三路都有權喝水，問題是未交代取得，不是禁止共通新增動作。
- **修訂結果（2026-11-26）：** A 分支已明寫走廊散步後回辦公室；C 分支修為仍在桌前寫紙，不再暗示先離桌再返回；17:20 共通段移除只在 B 分支提供的水杯假設。B08 章稿與 runtime 同步，見 `second-act-to-third-act-transition.md` 的追加複核。

### BET-04｜C 選項承諾寫完離桌，分支未履行（已修訂）

- **初次判定：** 舊 label 承諾「完成後就離開辦公桌」，但原分支只寫下第一步、沒有立刻離桌。
- **修訂結果：** 選項已改為「請她把明日第一步寫好，然後停下其他整理」，不再承諾離桌；C 分支只列第一步，推回其他文件並放下筆，明寫不再追加待辦，履行目前選項文字。共通段的後續站起離場發生於工作結束時，非被延後履行 C 的舊承諾。
- **驗證界線：** 選項 label 與分支文本同步；此項語義判斷不靠固定 validator 推定。

### BET-05｜緊急通知判定、外出可達性與離場手機位置（已修訂）

- **證據：** B08 intro 把手機放半開抽屜，說可以聽見緊急通知；A 離開辦公室且手機不在口袋，common 寫「除非確認為緊急事件」，卻無不查看內容時的確認方式；最後手機仍在抽屜，她不再打開便離場。
- **判定：** 本章沒有實際急件，不代表已驗證例外流程。留手機在辦公室也不必然不可能，但與保持緊急可達性的理由需一致。
- **推薦：** 用簡短劇情交代指定緊急聯絡方式（例如同伴可直接到走廊通知），普通訊息休息結束再看，不讓角色靠通知是否震動猜緊急程度。17:20 已檢查普通補件後，離場只把手機收入口袋、不解鎖；「不查看」不等於「不能攜帶」。避免讓休息變成失聯或保管遺漏。
- **範圍：** 這是虛構情節聯絡規則，不新增遊戲手機通知功能或裝置權限。
- **修訂結果（2026-11-26）：** 17:20 確認一則普通訊息後，陽奈把手機放進外套口袋再離場，不再把電話留在辦公室。新增明確規則：會影響安全或需當下判斷的值班異常，由當班同伴直接到陽奈所在位置說明原因；普通訊息延至休息結束再看。這補足故事中的通知渠道，不新增遊戲手機功能或未實作的通知系統。

### BET-06｜C01「昨天留下必要條件」不是 B08 各分支既有成果（已修訂）

- **初次判定：** C01 引用昨日共用清單上的任務必要條件，但當時 B08 A／B／C 分支看起來只有散步、喝水或個人設備回查，疑似沒有全路徑都可依據的例行任務交接。休息便條不能代替任務清單。
- **修訂結果：** B08 common 已把下一項例行任務的檢查範圍、資料來源與例外回報條件寫入共用清單，明確適用於 A／B／C；C01 可據此描述「昨天離開前」留下必要條件，並接續同伴早晨完成第一輪整理。C01 上午交接、下午核對的時間順序亦已明示。
- **驗證界線：** 章稿與 runtime 同步及固定 validators 確認文字／結構一致；不代表九種局部組合的瀏覽器通關或完整歷史旗標窮舉。後續 BET-07 另記休息與回查結果的時序修訂。

### BET-07｜C01 休息中仍寫任務表，回查結果到達兩次（已修訂）

- **證據：** common 已把筆放下、到窗邊開始十分鐘，隨後翻任務表寫「格式可以不同……」，再說「休息還剩三分鐘」。接著同伴敲門交回查、陽奈看完寫已確認，沒有休息結束／中斷提示。更早在休息之前，已有同伴「正把回查結果貼到任務表旁」。
- **判定：** 可能是預先貼進度、之後正式回報，但文本兩次都稱結果；不能無來源地視為兩項已完成兩次。新的十分鐘不要求完美，可中斷仍需說清理由，不能一邊做公務一邊宣告沒被填滿。
- **推薦：** 任務觀察備忘放休息前；第一次張貼改為回查進度／待查來源，或併入最後唯一回報。休息中同伴可先放資料，明說時間到後再讀，然後完成總表確認；若採真正急件中斷，需事件理由，當前兩項均無緊急性，不推薦新增急件。保留兩個例外各自的日期補齊／更換零件結果，不將其混成 B06 的例外數量。
- **修訂結果（2026-11-26）：** 休息前的任務表只標記兩項「待回查」，不先寫成結果；同伴在休息剩三分鐘時把未開啟的整理紀錄放到桌邊，約定休息後再確認，沒有先報告結果。陽奈完成剩餘休息後才核對日期補齊與設備更換結果。正式回查只在休息後進行一次，沒有在休息中重開公務。詳見 `second-act-to-third-act-transition.md`。
