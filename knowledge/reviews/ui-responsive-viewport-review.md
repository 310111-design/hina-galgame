# UI 2.0 公開頁響應式 viewport 初驗

日期：2026-11-24  
對象：`https://310111-design.github.io/hina-galgame/game.html`  
狀態：模擬 viewport 初驗完成；不等於實機或完整閱讀狀態驗收。

## 範圍與觀察

在正式 Pages 的 P01 一般對話畫面依序套用三種 Chromium 模擬 viewport，檢視主舞台、角色、對話區與功能操作按鈕。讀取 `document.documentElement` 尺寸及功能選單、音訊、已讀快進控制的 DOM 邊界；畫面上三組控制在各自 viewport 內，文件寬高均與 viewport 相同。

| viewport | 功能選單 | 音訊 | 已讀快進 | 文件尺寸 |
|---|---|---|---|---|
| 390×844 直向 | x=300–378, y=9–53 | x=304–378, y=97–139 | x=303–375, y=791–831 | 390×844 |
| 844×390 橫向 | x=734–822, y=4–48 | x=743–822, y=76–118 | x=698–776, y=340–382 | 844×390 |
| 1440×900 桌面 | x=1330–1418, y=15–59 | x=1339–1418, y=106–148 | x=1246–1324, y=840–882 | 1440×900 |

三種尺寸的視覺檢查均能看到主角色立繪和底部對話區；橫向及桌面版將角色與閱讀區改為左右／上下分配，沒有沿用直向時的放大配置。檢查後已清除 viewport override，恢復瀏覽器原始 390×844 尺寸。

## 限制與後續

- 本次只有 P01 一般對話；未檢查選項、長句、放大字體、大量紀錄、選單開啟、存檔畫面或逐字播放狀態。
- Chromium 模擬尺寸不能代表 iPhone Safari 的安全區、動態工具列、觸控手勢、音訊啟動或真實裝置縮放行為。
- 改版前後三種 viewport 的 PNG 已保存至 `knowledge/reviews/ui2-visual-baseline/`，來源、擷取方式及對照結論見 `knowledge/reviews/ui2-visual-baseline.md`。這補齊視覺基線保存，未補齊實體裝置 QA。
- 當次三種 viewport 的一般對話檢視沒有發現需改 CSS 的版面缺陷；其後對比度補充檢查找到並修正未選取選項邊界偏弱，靜態數值與限制見下節。不據此勾選 UI 2.0 實機或完整 QA。

## 2026-11-24 對比度補充檢查

以 WCAG 相對亮度公式檢查 `site/game.css` 的文字色與深色基底。`--ink` 對 `--bg`／`--panel`／`--panel-2` 為 16.37／14.64／15.91:1；`--muted` 為 8.77／7.84／8.52:1；紫、玫瑰與金色強調文字在三種基底的最低值分別為 8.17、10.21、12.32:1。角色 mood／音訊標籤的金色文字對半透明暗底以白色作最亮背景上限計算為 5.82:1。

檢查亦發現主遊戲未選取 `.choice` 外框原色 `#e9dcf044` 與對話面板最暗端 `#0b0913` 合成後約 2.00:1；現提高 alpha 為 `#e9dcf077`，同一端點計算為 3.87:1，仍沿用原色相及邊框尺寸。hover／focus／selected 狀態維持既有樣式。

這些數字是依 CSS token／已知底色做的靜態合成估算，不是瀏覽器取樣或全頁 WCAG 稽核；不能驗證漸層每個像素、背景圖片、色覺差異或所有功能元件的非文字對比。iPhone Safari、完整狀態矩陣與輔助科技 QA 仍待實機驗收。
